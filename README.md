# Explore With Me (Микросервисная архитектура)

Это приложение, позволяет пользователям делиться информацией о событиях и находить компанию для участия в них.
Представляет собой декомпозированную на независимые функциональные модули (микросервисы). 
Система спроектирована с учётом высокой отказоустойчивости (паттерн Circuit Breaker).
Также дополнена рекомендательной системой на базе истории просмотров событий и gRPC.

## Архитектура системы

### Выделенные сервисы

* **gateway-server (Port: 8080)** — Единая точка входа (API Gateway). Отвечает за маршрутизацию внешнего трафика к соответствующим микросервисам.
* **discovery-server (Port: 8761)** — Сервер регистрации и обнаружения сервисов.
* **config-server (Port: 8888)** — Централизованное хранилище конфигураций для всех модулей системы.
* **user-service** — Управление учетными записями пользователей.
* **category-service** — Справочник категорий мероприятий.
* **request-service** — Управление заявками пользователей на участие в событиях.
* **comment-service** — Сервис для публикации, редактирования и администрирования комментариев к событиям.
* **event-service** — Управление мероприятиями и подборками событий. Интегрировано с модулем фиксации статистики.
* **collector** — gRPC-сервер, который принимает в реальном времени логи действий пользователей (просмотры, регистрации на события, лайки) и транслирует их в Apache Kafka.
* **aggregator** — Фоновый обработчик. Вычитывает логи действий из Kafka, рассчитывает матрицу косинусного сходства между мероприятиями с учетом весов действий и отправляет результаты обратно в Apache Kafka.
* **analyzer** — Сервис хранения аналитики и gRPC-сервер. Параллельно вычитывает из Kafka логи и матрицы подобия, сохраняет их в PostgreSQL и предоставляет высокопроизводительное потоковое API (stream) для расчета персональных рекомендаций.

### ⚙️ Конфигурация системы

Все файлы конфигураций вынесены из кода и централизованно располагаются в модуле **config-server**. 
Настройки маршрутизации API Gateway и gRPC-взаимодействия заданы в application.yml и также располагаются в модуле **config-server**.

### 🔌 Внутренний API (Межсервисное взаимодействие)

* **Синхронный REST-контур:** Взаимодействие между микросервисами осуществляется в синхронном режиме по протоколу HTTP/REST с использованием клиентов **Spring Cloud OpenFeign**. 
Для предотвращения проблемы каскадных падений все Feign-клиенты защищены фабриками откатов (FallbackFactory) с механизмами **Resilience4j Circuit Breaker** и автоматическими повторами **Retry**.
Все внутренние эндпоинты изолированы и используют префикс /contract:
* **Синхронный gRPC-контур:** Высокоскоростное взаимодействие между event-service и модулем аналитики (collector, analyzer) построено на протоколе gRPC (HTTP/2) с использованием Protobuf-контрактов. 
Поддерживается буферизированный стриминг данных (stream) для пакетной передачи рекомендаций и рейтингов.
* **Асинхронный рекомендательный контур:** Стриминг аналитических логов и матриц подобия между модулями collector -> aggregator -> analyzer изолирован внутри топиков брокера Apache Kafka (stats.user-actions.v1 и stats.events-similarity.v1) с сериализацией данных в бинарный формат Apache Avro.

### 📲 Контракты взаимодействия (Примеры)

* GET /contract/user/usersIds — Пакетный сбор пользователей пачкой по списку ID для исключения проблемы N+1.
* GET /contract/event/eventIds — Пакетный сбор событий по списку ID для комментариев.
* GET /contract/category/categoriesIds — Пакетный сбор категорий.
* GET /contract/request/confirmed — Запрос счетчиков подтвержденных заявок для пачки событий.
* gRPC collectUserAction(UserActionProto) — Асинхронная фиксация действия пользователя (веса: VIEW = 0.4, REGISTER = 0.8, LIKE = 1.0).
* gRPC GetRecommendationsForUser(UserPredictionsRequestProto) returns (stream RecommendedEventProto) — Потоковый расчет персональных рекомендаций.

### 📖 Внешний API (Спецификация)

Внешний API предоставляет публичные (для гостей), приватные (для авторизованных пользователей) и административные (для модераторов) эндпоинты, доступные через шлюз http://localhost:8080.
Полная спецификация внешнего API со всеми схемами запросов и ответов доступна по ссылке: [Explore With Me — OpenAPI Спецификация](https://github.com/yandex-praktikum/java-plus-graduation/blob/ci/.github/workflows/stuff/postman/recommendations/ewm-main-service.json).
